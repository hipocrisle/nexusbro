# Обычные вкладки CEF и проверка dev

Внутри каждой супер-вкладки теперь есть обычные вкладки: открыть, выбрать,
закрыть, закрепить и открепить. Адресная строка, назад/вперёд и обновление
управляют выбранной страницей. Ссылки `target="_blank"` открывают обычную
вкладку. После закрытия последней остаётся одна пустая страница.

## Устройство

Супер-вкладка сохраняет собственный ОС-процесс, профиль и прокси. Обычные
вкладки — несколько `CefBrowser` этого процесса, с общим request context.
Контейнер показывает только выбранный браузер и передаёт размер всем его
страницам. Linux-контейнер использует root visual/colormap, Windows — дочернее
окно STATIC. Окна страниц не перевстраиваются через SetParent.

Протокол родителя и движка:

- stdin: строки JSON с `deystvie` (`novaya`, `vybrat`, `zakryt`, `zakrepit`,
  `pereyti`, `nazad`, `vpered`, `obnovit`);
- stdout: `NB-OKNO <handle>` для готовности контейнера и
  `NB-VKLADKI <json>` для состояния обычных вкладок;
- в оболочке команды пишет отдельный поток через ограниченную очередь.
  Ожидание окна и чтение событий также идут вне UI-потока;
- события CEF превращаются в сообщения внутренней очереди; создание браузеров
  и команды CEF исполняются в потоке его message loop.

`obychnye.json` в профиле хранит адреса, заголовки, порядок, закрепление,
активный ID и счётчик. Родитель проверяет поколение запуска перед принятием
снимка и записывает JSON через временный файл и rename. Запись синхронизирована
с удалением профиля. Повреждённый JSON сохраняется как
`obychnye.povrezhdena.json`; вместо него открывается пустая страница.

Режим «Открывать пустой» начинает заново с адреса из настроек. При выключенном
режиме восстанавливается JSON-сессия. История назад/вперёд работает в текущем
браузере; её стек в JSON пока не сохраняется. Cookies и остальное хранилище
страниц остаются в отдельном профиле CEF каждой супер-вкладки.

При клике по интерфейсу оболочка возвращает клавиатуру собственному окну/
WebView. Это важно: DOM-фокус поля сам по себе не возвращал фокус X11 из CEF.
Принудительного фокуса чужому процессу со стороны оболочки нет.

## Проверка слияния

Исходный `dev` на `c3abac5` собрался, но GUI-проверка остановилась после
повторного открытия: контейнер был `IsUnMapped`, хотя вкладка считалась
готовой. Фоновое завершение запуска могло применить устаревшую видимость
после команды показа. Применение видимости теперь сериализовано отдельно
от списка вкладок и всегда использует актуальное состояние.

Изменения Kimi были в истории, но merge не сохранил проверку снимка сторожа.
Вместо поиска окна по устаревающему снимку сторож теперь проверяет текущий
`Child::try_wait` под коротким захватом состояния, а ресурсы очищает после
его снятия. Удаление супер-вкладки сохраняет владение её процессом до остановки.

Повторный полный бенч с обычными вкладками: [результаты](verification/dev-supertabs.json).
Открытие существующего профиля — **448–640 мс**, правка — **520 мс**,
удаление — **91–168 мс**, переключение — **89–92 мс**.
Максимальный интервал UI-таймера за стресс-прогон — **65 мс**.
Холодное создание нового профиля заняло **2,52 с** до готового CEF при
продолжающем отвечать интерфейсе; второй профиль — 504 мс.
Проверены также удаление остановленного запуска, правка во время запуска,
20 повторных переключений, отсутствие лишних движков и возврат из диалогов.
[Перезапуск и resize базового исправления](verification/dev-autorestore.json) проверены отдельно; для обычных вкладок повторный запуск и размеры проверяет новый сценарий ниже.

## Проверка обычных вкладок

[Итог](verification/ordinary-tabs.json), [снимок](verification/ordinary-tabs.png),
[видео физических кликов и ввода](verification/ordinary-tabs.mp4).

Сценарий `tests/gui/ordinary_tabs.py` использует локальный HTTP-сервер и
изолированные данные. Проверены:

- создание трёх браузеров в одном процессе, ввод в страницу и адресную строку;
- popup-ссылка, назад/вперёд, обновление, закрытие;
- три нативных дочерних окна, видимость только выбранного, resize всех страниц;
- закрепление/открепление, включая кнопку с клавиатуры;
- общие cookies внутри супер-вкладки и изоляция между двумя супер-вкладками;
- закрытие последней обычной вкладки с возвратом пустой страницы;
- сохранение и повторное открытие супер-вкладки с двумя обычными вкладками;
- восстановление адресов, порядка, закрепления и выбора после перезапуска;
- автостарт только активной супер-вкладки;
- 25 команд при SIGSTOP движка, отзывчивость оболочки и отсутствие лишних процессов;
- отсутствие живых движков после штатного выхода.

Запуск после `npm run build` в `desktop` и `cargo build` с настроенным `CEF_PATH`:

```bash
Xvfb :94 -screen 0 1280x900x24 -nolisten tcp
python3 tests/gui/ordinary_tabs.py --display :94 --port 9223
```

Нужны `websocket-client`, Pillow, xdotool, xwininfo и ffmpeg. Скрипт отказывается
подключаться к уже занятому порту инспектора. Результаты и временные данные
по умолчанию находятся в игнорируемом `.dev-check/`.

Два теста формата сессии: `cargo test --lib sessiya::tests` с доступным CEF.
Они проверяют восстановление полей/ID и сохранение повреждённого исходника.
Linux-сборка и тесты прошли. Windows проверена командой
`cargo check --target x86_64-pc-windows-gnu --features cef/dox`:
это проверка типов без линковки нативного CEF. Windows GUI проверяет пользователь.
В 0.2.5 CI успешно собрал полный Windows MSVC-установщик, но пользователь
обнаружил чёрную область страниц. В 0.2.6 Windows переведена на штатный
CefRunMessageLoop с командами на том же CEF UI-потоке; добавлены Alloy runtime,
порядок HWND, диагностика и управление интерфейсом. Подробности и границы
проверки — [описание 0.2.6](RELEASE-0.2.6.md).

Следующий этап: runtime-проверка Windows, дальнейший перенос профилей/VPN
и флагов приватности; затем клавиатурные команды из страницы и загрузки.
