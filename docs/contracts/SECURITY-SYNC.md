# Passwords and isolated account sync — implementation contracts

Owner explicitly requires a separate browser account and complete isolation from NexuSSH. Reuse reviewed algorithms/source only: NEVER its server URL, DB, tokens, keys, accounts or service. No production service/proxy/Telegram changes in this work. Prepare isolated backend + deployment artifacts; native Rust builds on GitHub only.

## Ownership
- Root: all existing files, Cargo manifests/lock, Tauri registrations, password CEF bridge, adapters into real browser data, native menus, regression/native acceptance/release.
- vault agent: ONLY new `desktop/src-tauri/src/secure_vault.rs`, `tests/security_vault_*`, optional dedicated dependency manifest proposal. No existing-file edits.
- account agent: ONLY new `desktop/src-tauri/src/browser_account.rs`, `desktop/src-tauri/src/browser_crypto.rs`, `sync-server/**`, `tests/security_account_*`. No existing-file edits. Own server MIT attribution. No deploying, no paid API, no NexuSSH writes.
- UI agent: ONLY new `desktop/src/SecuritySettings.tsx`, `desktop/src/securitySettings.css`, `desktop/src/security.ts`, `tests/security_ui_*`. No existing-file edits.

## Vault API (non-Tauri)
`VaultState: Default` methods all `&self`: `status()->VaultStatus {exists:bool,unlocked:bool}`; `create(root:&Path,password:&str)->Result<(),String>`; `unlock(root:&Path,password:&str)`; `lock()`; `get(key:&str)->Result<Option<Zeroizing<String>>,String>`; `put(key:&str,value:&str)->Result<(),String>`; `remove(key:&str)->Result<(),String>`; `keys(prefix:&str)->Result<Vec<String>,String>`. root is app data dir, filename `browser-vault.v1`. Envelope random DEK, bounded Argon2id + AEAD, fresh nonce each write, authenticated version/header, atomic write/backups, 0600 on Unix. No retained master password, no plaintext disk, zeroize keys/buffers, no secret logs. Locked operations fail. Inactivity lock backend enforced, explicit lock. Min password 12 chars. Wrong password/corrupt files never overwrite originals.

## Trusted IPC owned by root
`security_vault {action:'status'|'create'|'unlock'|'lock', password?:string}` -> VaultStatus.
`security_passwords {action:string, data?:object}`: list -> CredentialSummary[]; save -> summary; delete -> {}; capture {super_id,tab_id}->draft summary (password remains backend); save_draft {draft_id,username,title}->summary; fill {id,super_id,tab_id}->{}; reveal {id}->string only explicit owner action.
CredentialSummary `{id,origin,username,title,super_id,updated_at}`; saved plaintext password NEVER in list/status. `save` data includes origin,username,password,title,super_id for manual creation. HTTPS only (loopback fixtures exception in test mode), exact-origin binding, private tabs excluded, explicit user action for fill; never cross-origin/frame automatic disclosure. Capture uses native trusted response, no page-console credential transport.
`security_account {action:string,data?:object}` actions status/configure/register/login/logout/totp_enroll/totp_verify/totp_disable/recover/change_password/delete_account. Account status `{configured,logged_in,username,server,totp_enabled}`. configure `{server}` HTTPS only; backend endpoint initially empty rather than fabricated availability. Register/login `{username,password,totp?}`; registration returns `{recovery_key,...status}`; enrollment returns `{secret,otpauth_uri}`; verify `{code}` -> `{recovery_codes?:string[],...status}`. Separate local master and account passwords. Account tokens/remembered key only inside vault. TLS errors must fail closed. Redacted transport errors.
`security_sync {action:'status'|'configure'|'run',data?:object}`. Selection `{settings:boolean,bookmarks:boolean,supers:string[],passwords:string[]}` all off by default. status `{selection,last_sync?,available_supers: {id,name}[],report?}`. run -> `{pushed,pulled,conflicts:string[],errors?:string[]}`. Root applies portable whitelisted data, excludes cookies/sessions/private/history/downloads/proxy credentials; per-Super and per-password opt-in. Unchecking stops sync, never deletes another device. Explicit deletion uses authenticated tombstones. Conflicts preserve both/require choice, never silently lose local edits. No raw profile sync.

## Account backend API
`AccountState:Default`; `pub async fn dispatch(vault:&VaultState,action:&str,data:serde_json::Value)->Result<serde_json::Value,String>` (may be associated method `state.dispatch`). Pure crypto in browser_crypto, adapted NexuSSH account_crypto (MIT) with browser domain separation, independent keys. Account config/session persisted via vault API above. Agent defines public `SyncItem {id:String,value:String,modified:u64,deleted:bool}` and `pub async fn exchange(vault:&VaultState,items:Vec<SyncItem>)->Result<SyncExchange,String>` (associated state method okay), `SyncExchange {remote:Vec<SyncItem>,pushed:usize,conflicts:Vec<String>}`. Root only supplies selected namespaced IDs `nexusbro.v1/<kind>/<opaque id>`, root owns merge/selection tracking. Persist bounded revision/hash metadata per account. AEAD binds full item ID. Server sees ciphertext only. Browser server allows own item namespace/types, rejects SSH items. Handle pagination, bounded retries/timeouts, replay/conflict protection. DO NOT have disabled categories uploaded or applied; don't erase remote because absent locally. Own independent server tests for auth/TOTP/recovery/namespace and 2-client encrypted roundtrip. No need to rewrite crypto; copy/adapt maintained source and include license.

UI component default `SecuritySettings({onClose}:{onClose:()=>void})`. Tabs passwords/account/sync, unlock/create gates; show-once recovery info; explicit enable confirmation for TOTP, clear secret fields on submit/unmount; native select forbidden, use Vybor and Icon chevronDown (no Unicode arrow). Counts/status honest. No SUCCESS for unconnected backend. Root mounts within existing settings navigation.
