# NexusBro 0.2.17 — приёмка

Статус: кандидат, ещё не опубликован. Публичное автообновление — 0.2.16.
Код приложения и подписанных пакетов: fd3a110. Последующие изменения —
только исправления клиента UI Automation и документация.

Изменения:

- Меню плюса, трёх полосок, Super, вкладок, адреса и страницы используют тему
  NexusBro. Открытый сайт остаётся видимым. Подсказки адреса тоже оформлены
  приложением: нативный datalist больше не перехватывает клавиатуру.
- Регистрация и вход автоматически подключают отдельный сервис NexusBro.
  Свой настроенный сервер сохраняется; ручной URL доступен дополнительно.
- Средняя кнопка/Ctrl+клик и ПКМ открывают ссылку в новой вкладке той же Super,
  сохраняя приватность и исходную активную вкладку при фоновом открытии.
- Существующее хранилище требует мастер-пароль при запуске до загрузки сайтов.
  Ctrl+Shift+L блокирует все окна и хранилище; DevTools закрываются.
- После разблокировки сохраняются вкладки и работоспособные native CEF views.
  Linux скрывает внешние окна, сохраняя mapped-состояние вложенных renderer-окон.
- Пояснено сохранение логинов: создать локальное хранилище, войти на сайте,
  подтвердить сохранение. Облачный аккаунт для локальных паролей не нужен.

Подтверждённая приёмка кандидата:

- Сборка пакетов 44365273812 (fd3a110): security и Linux SUCCESS; Windows
  скомпилирован и упакован, первоначальный UI-прогон остановился на временном
  узле без типа в UI Automation (KeyError None). Это не названо общим SUCCESS.
- Windows 44369991526: SUCCESS на том же подписанном установщике из
  44365273812, клиент теста bf51272. 59 записей, включая нативный фокус,
  Ctrl+Shift+L из сайта и адреса, видимую страницу после unlock и startup master.
  В журнале подтверждён вызов native WebView2 accelerator, снимок после
  разблокировки просмотрен. Отчёт: verification/0.2.17/windows-results.json.
- Linux 44365273812: SUCCESS, 32 записи, настоящий бинарник fd3a110.
  Два Tauri/CEF клиента и настоящий изолированный sync-сервис: регистрация/вход
  без URL, capture с согласием, actual DOM fill, запрет другого origin/private,
  выборочная синхронизация, конфликты/удаления, startup master/wrong password/
  restart и отсутствие открытых секретов в проверенных файлах/логах/серверной БД.
- Главное и дополнительное окна показывают зелёную контрольную страницу
  до блокировки и после разблокировки: RGB (24,85,65) в трёх точках каждого
  native view. Обе восстановленные страницы принимают физический клик
  и отправляют trusted submit. Снимки просмотрены вручную.
  Машинный отчёт: verification/0.2.17/native-security-results.json.

Предыдущие зелёные DOM-проверки не были приняты за визуальную приёмку:
просмотр снимков выявил чёрный renderer после lock/unlock. Причина — отдельный
unmap вложенных X11-окон без соответствующего восстановления. Исправление
726cbe4 и новые проверки пикселей/физического ввода закрывают этот пропуск.
Bare Xvfb не имеет оконного менеджера; тест явно выбирает нативное окно
оболочки перед отправкой shell-клавиш, а не полагается на DOM activeElement.

CI: кэш CMake/Rust привязан к версии runner image, чтобы смена установленного
MSVC не оставляла путь к старому linker. Ubuntu использует реальные mirrorlist
файлы GitHub runner с основным зеркалом; установка зависимостей ограничена.
Production sync в этом выпуске не меняется. Публичный HTTPS health проверен.

Проверить владельцу после уведомления о готовом автообновлении:

1. В «О программе» версия 0.2.17.
2. Меню и подсказки адреса используют выбранную тему, сайты остаются видимыми.
3. Средняя кнопка и ПКМ по ссылке работают в обычной и приватной Super.
4. Создать хранилище, войти на сайт, подтвердить сохранение, выбрать заполнение.
5. Перезапуск требует мастер-пароль; Ctrl+Shift+L скрывает все окна; после
   разблокировки сайты видны и принимают ввод. Это пароль хранилища, не аккаунта.
6. Регистрация/вход без URL, 2FA/recovery, выборочная синхронизация двух устройств.
7. Регрессии: цвета/приватность Super, очистка нужной Super, история/загрузки,
   DevTools, подсказки URL и автоперевод.

Публикация использует существующий workflow publish-tested: тег должен точно
совпадать с commit сборки, Linux должен пройти приёмку; тот же установщик
Windows проходит ещё один свежий physical-прогон, затем проверяются подписи
трёх пакетов и манифест. Публикуются именно проверенные подписанные пакеты.
Публичная проверка после публикации ещё предстоит.
