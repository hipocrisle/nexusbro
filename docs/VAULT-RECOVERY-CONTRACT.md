# Сброс и восстановление мастер-пароля

Поведение соответствует NexuSSH VaultLockScreen/vault_reset/vault_restore_backup: забытый мастер-пароль не расшифровывается; явный сброс сохраняет прежнее хранилище зашифрованным, новое пустое хранилище получает новый мастер-пароль. Восстановление копии требует прежний пароль; текущее хранилище перед заменой также архивируется. Облако не удаляется и не перезаписывается автоматически. Cookies, профили сайтов, обычные настройки и вкладки не удаляются; сохранённые пароли, локальный доступ к аккаунту и защищённая история находятся в старой копии.

В отличие от удаления файла, замена выполняется атомарно: до публикации нового файла старый остаётся основным. Ни штатный сброс, ни ошибка/перезапуск не должны создавать окно обхода стартовой блокировки. Ошибка архивирования запрещает замену. Имена копий генерируются программой, API принимает только непрозрачный ID, не путь; никаких symlink/обхода каталогов. Восстановление проверяет пароль и целостность ДО замены. Все копии только ciphertext, с закрытыми правами и без автоматического удаления. Нельзя выполнять сброс без точного подтверждения «СБРОСИТЬ».

## Контракты модулей
Core (агент): только desktop/src-tauri/src/secure_vault.rs. Публичные VaultBackup {id:String,created:u64}; VaultState::recovery_backups()->Result<Vec<VaultBackup>>, reset_with_password(password:&str)->Result<VaultBackup>, restore_recovery_backup(id:&str,password:&str)->Result<VaultBackup>. configure(root) уже вызывается. Сброс требует существующее хранилище и password>=12, возвращает архив прежнего; restore проверяет пароль выбранного архива и возвращает архив заменённого текущего. После успеха vault unlocked с новым/восстановленным содержимым; при ошибке остаётся locked, файлы/основной ciphertext сохраняются. Сериализация существующим inner mutex. Подробные тесты в этом же модуле; Cargo только CI.

Root: browser_lock.rs, lib.rs, BrowserLock.tsx/CSS, SecuritySettings.tsx, frontend и native UI тесты, CI и релиз. IPC browser_vault_backups -> Vec<VaultBackup>, browser_vault_reset(password,confirmation)->LockStatus, browser_vault_restore(id,password)->LockStatus. Только доверенный shell, serial BrowserLockState; reset/restore только при browser locked. За блокировкой добавить только эти whitelist команды. На успехе общий путь unlock, без раннего раскрытия сайтов/старых секретов. Отказ оставляет browser locked. Ссылка «Забыли мастер-пароль?» на lockscreen; в настройках доступ через блокировку. Без системных confirm/prompt, собственная тёмная форма, новый пароль и повтор, явное предупреждение потерь и подтверждение. Копии выбираются по дате, путь не показывается.

Приёмка: новая пустая vault/старый backup decryptable OLDonly; wrong restore не меняет current; восстановление OLD возвращает секреты и архивирует NEW; restart требует master; realnativeUI reset+restore; cancel/error не открывает CEF; никакого clouddelete/autooverwrite. Нативные сборки только GitHub CI.
