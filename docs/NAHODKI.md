2. **Старый procmon-захват прошлой сессии (cap.pml, 1 ГБ, 19:20–19:23).**
   Сконвертирован в cap.csv (469 МБ, 2 615 809 строк). Нюанс: procmon без
   elevation отказывается работать (exit 1, молча) — нужен
   `Start-Process -Verb RunAs`, user подтверждает UAC.
3. **cap.csv (19:20–19:23):** nexusbro.exe pid 1760 жив весь кадр (Process Exit
   нет — конец кадра = конец прошлой сессии). Активность: TCP к github.com

   `%LOCALAPPDATA%\NexusBro\` — ни vkladki.json, ни профилей. НОЛЬ событий
   Singleton*/lockfile по профилям. cim_log.txt прошлой сессии пуст → движок

4. **Данные user'а:** vkladki.json = `[]`, aktivnaya.json = "svmwarlh09".
   Оба профиля (svmwaq6z29, svmwarlh09): `exit_type: Crashed` в Preferences —
   подтверждает находку №3 (выход программы = job object kill, не WM_CLOSE).
5. **PROBA-запуск (NEXUSBRO_PROBA=1, 19:34):** `САМОПРОВЕРКА: ok=true`.
   CIM-поллер (150 мс) поймал всё дерево движка: главный pid 22248,
   PPID 24528 (= nexusbro.exe), дети: renderer ×3, gpu, network, storage,

   --enable-features=WebContentsForceDark --enable-logging=stderr about:blank

   - Дубликат с тем же профилем: вышел сам, **ExitCode=0** → singleton

     новый главный pid 3280 = `CreateFile` по lockfile. Lockfile живёт как

## Что нашла (главное)

- **Singleton и блокировки профиля на движке 157 работают штатно** — и
  «переслать и выйти 0», и «после убийства не остаётся». Жалоба «движок умер
  сразу (exit 0)» НЕ воспроизводится при живом первом экземпляре; если
  возникнет — искать гонку: дубликат стартовал ДО того, как первый открыл
  lockfile (окно между CreateFile-попытками), либо первый уже умирал.
- **Встраивание окна работает** (дочернее Chrome_WidgetWin_1 без рамки под
  полосой вкладок) — как и было установлено руками днём.
- **АНОМАЛИЯ: окно приложения само стало минимизированным.** В 19:34 окно
  NexusBro нормальное (rect 1912,-8 1296x859, второй монитор), к ~19:36 —
  (-32000,-32000 160x28, WS_MINIMIZE). Никто его не минимизировал осознанно.
  Кандидат на жалобу «живёт своей жизнью»: проверить window-state plugin
  (восстановление «свёрнуто») и сторож окон.
- Процесс движка при ручном перезапуске: стартовавший pid (35824) вышел,
  а дерево продолжил под pid 3280 — детали самоперезапуска Chromium в nb2.csv
  (Process Start события), не разобрано.
