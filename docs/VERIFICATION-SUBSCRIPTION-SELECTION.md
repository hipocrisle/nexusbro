# Выбор узла VPN-подписки и повторная проверка dev

Проверка 13.11.2026. База — dev `c3135f4` (0.2.6). Релиз не публиковался.
Руководство проекта и REPORT-codex перечитаны перед проверкой.

## Изменение этапа 4 CEF-roadmap

В форме создания/правки супер-вкладки можно загрузить узлы HTTP(S)-подписки
и выбрать конкретный узел. Адрес подписки остаётся в `proxy`, выбранная
ссылка — в новом `proxy_uzel` в vkladki.json/sohranennye.json.
При запуске подписка загружается заново, выбранная ссылка сверяется со списком.
Если узел исчез, запуск завершается понятной ошибкой без переключения на другой.
Старые профили без поля продолжают выбирать первый узел.

Запрос списка асинхронный; смена адреса и закрытие формы отменяют применение
устаревшего ответа. Ошибка остаётся в форме, отмена доступна. При смене адреса
выбор очищается. Для увеличенной формы добавлена прокрутка в пределах окна.
Сам туннель по-прежнему поддерживает VLESS; новые протоколы не добавлены.

## Проверка

- `npm run build` и `CEF_PATH=... CARGO_BUILD_JOBS=2 cargo build` успешны.
- `cargo test --lib vpn::proverki`: 6 тестов, включая выбор второго узла,
  отсутствие выбранного узла и пустую подписку.
- GNU Windows `cargo check --offline --target x86_64-pc-windows-gnu --features cef/dox`
  успешен. Это проверка типов без нативной линковки CEF, не Windows GUI.
- Исходная dev прошла полный `gui-supertabs.py --stress`: открытия 296–432 мс,
  правка 395 мс, закрытия 152–160 мс, максимальный UI-интервал 45 мс.
  Холодное создание нового профиля — 2,19 с, критерий <1 с относится к повторному открытию.
- Итоговая сборка прошла тот же полный стресс-прогон: повторные открытия
  388–796 мс, правка 362 мс, закрытия 156–168 мс. Максимальный UI-интервал
  697 мс на стресс-сценарии (ниже порога 1 с, но выше исходного прогона);
  блокирующих слоёв и живых процессов профиля после штатного выхода нет.
- `tests/gui/ordinary_tabs.py` прошёл физическими кликами/вводом: обычные вкладки,
  CEF-страница (проверен пиксель), меню, фокус, панель, настройки, cookie, сохранение,
  перезапуск приложения/автостарт только активной, 25 команд при SIGSTOP.
  Максимальный UI-интервал 26 мс; после выхода живых движков нет.
- Новый `tests/gui/vpn_subscription.py`: настоящий локальный HTTP-сервер подписки,
  сервер xray VLESS, клиент xray приложения и настоящий CEF. Первый узел недоступен,
  второй выбран физически в форме. Страница `vpn-fixture.test` доступна только
  через VLESS: сервер xray перенаправляет её в локальный HTTP fixture, остальные
  запросы блокирует. В журнале подтверждён запрос именно этого домена.
  Проверены сохранение выбора на диске/после перезапуска, форма правки/обновление
  списка, удаление выбранного узла без fallback и оставшихся процессов,
  ошибка HTTP 503 и отмена формы без блокирующего слоя.

Результаты: [JSON](verification/subscription-selection/).
Для повторения нового сценария после сборки:

```bash
Xvfb :94 -screen 0 1280x900x24 -nolisten tcp
python3 tests/gui/vpn_subscription.py --display :94
```

Нужны `websocket-client`, `xdotool` и xray в `desktop/src-tauri/binaries/`
(сервер теста) и `target/debug/binaries/` (клиент приложения). Порт 9223 должен
быть свободен. Данные создаются отдельно в игнорируемом `.dev-check/`.
Тестовая VLESS-связь без TLS используется только на loopback.
Windows-отрисовка по-прежнему требует реального runtime-подтверждения.
