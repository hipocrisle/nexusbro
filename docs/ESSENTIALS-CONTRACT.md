# Единый выпуск: повседневные функции браузера

Статус: выполнено и опубликовано одним выпуском 0.2.23; [приёмка и публичные доказательства](REVIEW-0.2.23.md).

Владелец 23.11.2026 утвердил все шесть предложений по порядку и один итоговый билд. Промежуточных публикаций нет. Пакет включает накопленный баг стартового подтверждения обновления. Засыпание целого движка и длительный soak остаются в отдельном ресурсном плане: не подменять их этими шестью пунктами.

1. Поиск по вкладкам/Super: существующие live snapshots и сохранённые определения, без запуска движков при поиске. Выбор результата активирует точную вкладку своего профиля/пути; lock/private не раскрывают данные за пределами существующей модели доступа.
2. Восстановление после сбоя: прежние обычные окна/вкладки/маршруты, lazy startup; приватные URL и сессии не сохранять. Атомарная запись, устойчивость к обрыву/повреждению.
3. Защита синхронизации: recoverable удаления/изменения Super и явный откат, без оживления удалений при каждом sync, без раскрытия паролей/ключей; история локальная и ограниченная.
4. Диагностика: фактический effective route и причины network/DNS/TLS/proxy, никакого Direct fallback и утечек credentials в UI/логи.
5. Диспетчер задач: отдельное окно/диалог по запросу, реальные owned-process метрики, без фонового постоянного polling. Никаких ложных per-tab RAM если процесс общий.
6. Резервные копии: настройки/закладки/структура Super отдельно от паролей; пароли только зашифрованно, без auth/cookies/private/ключей устройства в обычном экспорте. Валидация/preview импорта до изменения, атомарность/откат.

Границы параллельных пакетов: root владеет App.tsx/новыми search UI/backend wiring/lib.rs и общим меню. Агент recovery — sessiya.rs + новые recovery-модули/тесты; sync — browser_sync.rs + новые sync-history-модули/тесты; updater — updater.ts и его тесты. Общие lib.rs/App.tsx не редактировать агентам, отдавать root точные integration hooks. Другие пакеты после первичных контрактов. Каждый агент отдельный Git worktree от зафиксированной базы, no build/CI/release/versions/backend deploy. Только root объединяет и запускает проверку. Никаких native сборок на DE-1, secrets/env/services/proxy/paid fallback не трогать.
