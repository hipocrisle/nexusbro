# NexusBro 0.2.21 — кандидат, ещё не опубликован

Публичная версия пока 0.2.20. Кандидат объединяет индивидуальные маршруты вкладок, исправления облака и полностью автоматический UX памяти по отзыву владельца.

Облако — настоящая отдельная кнопка рядом с кнопкой супервкладки, без вложенных button. Используется прежний security_sync run с сохранённым выбором; никакого автоматического включения локальных записей. Состояние зелёное только после свежего native ACK. Click/Enter/Space, busy/dedupe, ошибки/конфликты и retry, отсутствие запуска сохранённых движков/переключения вкладки/скрытия CEF проверяются Chromium-фикстурой и нативной приёмкой с настоящим изолированным sync-server.

Ручные memory-пункты и диалог удалены. Автоматическая политика включена по умолчанию, 30 минут; медиа/ввод/загрузки и другие unsafe/unknown страницы не выгружаются. Никаких ручных keep/unload не требуется. Старый memory_keep не создаёт невидимого вечного исключения. Восстановленные невыбранные страницы остаются lazy.

Новый нативный Windows-gate не отправляет manual unload/keep и не включает автоматическую экономию вручную. Он проверяет default ON, lazy страницы без запросов, отсутствие manual memory меню, сохранение активной страницы сверх idle-интервала, настоящий Win32 scroll, 15 секунд реального minimize, автоматический close в свёрнутом состоянии, пять private commit сэмплов и ≥64 МиБ освобождения, прежние cookie/localStorage/scroll. HTML playing/paused и WebAudio часы, локальный RTC, черновик/загрузки/DevTools/private/pinned защищены автоматически. 120-секундный WAV исключает ложное совпадение из-за modulo короткого loop. Короткий таймер 8 секунд включается только для изолированного TEST_DATA; нормальный UI показывает 30 минут и закрывается через «Отмена», без Save/toggle.

Локальные TS/Vite и bundled Chromium cloud fixture прошли; нативные результаты кандидата ещё ожидаются. Изменений production services/env/Telegram/proxy нет. Сборки и CEF только на GitHub.

Индивидуальные маршруты теперь интегрированы в исходники приложения: строгий локальный intent, селектор UI, parent singleflight и native ACK с engine/window/tab/browser/attempt identity, ограниченные transports и RequestContexts на effective путь. Владелец явно согласовал отдельную авторизацию между путями и общий профиль для одного пути внутри Super. Старый Default не переносится. Ошибка пути не разрешает Direct fallback. Спячка целых супервкладок остаётся после маршрутов: [SUPER-HIBERNATION-PLAN.md](SUPER-HIBERNATION-PLAN.md).

Ограничение владельца соблюдается: отдельного выпуска cloud/memory не будет; следующая сборка включает маршруты. Предыдущий `44726617074`, запущенный до указания, отменён намеренно. Общая native-приёмка запущена; результаты ниже фиксируются отдельно от готовности выпуска. Публичная версия остаётся 0.2.20, тега 0.2.21 нет.

До остановки: native Linux реально выполнил sync по клику, проверил per-record ACK/local/private/saved и шифрованный обмен двух устройств. Первый pixel-check был перекрыт GTK tooltip; test-only `219a0e7` отводит настоящий курсор, не ослабляя цветовой порог. Повторный `44728897304` прошёл эти проверки и остановился позже: тест ошибочно ожидал сайт на ещё lazy-странице после restart. В `328fadb` тест сначала открывает выбранную страницу настоящим кликом; это ещё НЕ перепроверено нативно. Windows auto-only/minimize приёмка кандидата не выполнена. Не выдавать частичные результаты за завершение.

18 контрактных тестов реальных `tab_routes.rs` и `memory_guard.rs`, а также 59 тестов sync-server прошли в CI. UI TypeScript проверен. Independent source review нашёл и помог исправить waiter cleanup race и опасное смешивание нового key со старым engine proxy. Ни parser, ни review не доказывают native runtime. Требуются реальные одновременные пути/профили, HTTPS CONNECT, отсутствие Direct при сбое, restart, медиазащита/rollback, очистка исторических профилей и сохранность auth старого Default. Поддержка per-context `webrtc.ip_handling_policy` в точном CEF156 проверяется runtime fail-closed; до этого нельзя объявлять маршруты работающими. Ограничения: восемь путей на Super/engine; глобальные лимиты относятся к override Xray, существующие базовые туннели считаются отдельно.

Windows capability отдельно проверен, [сырой результат](verification/routes/windows-capability.json), [provenance](verification/routes/provenance.json). Его HTTP-успех не является продуктовой приёмкой. Подробные контракты: [TAB-ROUTES-PLAN.md](TAB-ROUTES-PLAN.md).

## Проверенные этапы кандидата

Источник приложения `44db912`, общий прогон [44756375098](https://github.com/hipocrisle/nexusbro/actions/runs/44756375098): обе платформы собраны; security, Linux smoke и Windows physical (60 проверок) прошли. Нативный Linux подтвердил HTTP/HTTPS CONNECT, совместное хранилище одинакового effective пути, изоляцию разных путей и Super, выбор пути у новой пустой вкладки, параллельные страницы на разных путях, реальный STUN/srflx у Direct и отсутствие STUN UDP у VPN в ограниченном окне наблюдения, блокировку неизвестного ID подключения.

Это частичная приёмка. Затем тест ошибочно переключил только backend Super, оставив прежнюю Super в интерфейсе; `c9874e4` переводит управление на настоящие клики с проверкой owner/tab/URL. Windows route-тест не начался из-за зависшего интерактивного импорта CA; `2213791` использует неинтерактивный LocalMachine Root только в одноразовой машине GitHub, с проверкой установленного thumbprint. Проверка TLS не отключается. Повторная приёмка [44761116467](https://github.com/hipocrisle/nexusbro/actions/runs/44761116467) использует те же бинарники; совпадение исходников desktop проверяется workflow.

Отдельная фикстура в настоящем Chromium прошла 32 сценария renderer safety. Исключение для opaque `about:blank` разрешает только подтверждённую native-owned пустую страницу и настоящую DOMException SecurityError от недоступных API; обычные opaque/data страницы, ввод, WebAudio и изменённые API защищены. Нативный переход owned blank на B подтверждён выше; это не заменяет общую CEF-приёмку.

Парное измерение ресурсов [44761313207](https://github.com/hipocrisle/nexusbro/actions/runs/44761313207) выполняется на одной Windows VM: публичная 0.2.20 и кандидат, 8 Super, 1000 сохранённых и 24 реально открытые страницы. Обе версии используют один alias loopback через настоящий HTTP proxy; проверяется фактический absolute-form request target. До получения полных трасс и метрик улучшение или отсутствие регрессии не заявляется.

Повторный прогон `44761116467` выявил плавающую гонку пустой вкладки: `runImmediately` захватывал старый initial document, а затем fresh `location.replace` создавал новый; задержанное сообщение старого token могло израсходовать GET epoch нового. `fae0fc8` убирает immediate capture и сохраняет раннее наблюдение только свежего документа. Native guards не разрешают неизвестный GET, POST или ввод. Windows physical снова прошёл, импорт CA завершился, но route fixture не подключилась к WebView2 inspector; причина ещё диагностируется.

Первое парное измерение `44761313207` прошло проверку нагрузки и трасс, но относится к предыдущему бинарнику `44db912`. CPU машины reference→candidate: active 1,842→2,741%, covered 1,126→1,841%, minimized 1,385→1,331%, restored 0,768→0,717%. Private commit после восстановления 1294,7→1309,3 МиБ, по 71 процессу. Рост active не ограничивался стартовым sample; у covered заметна посторонняя нагрузка VM. Все 24 страницы обеих версий дали полные trusted history; 72/72 кандидатных сценария прошли, скрытый rAF нулевой, восстановленный ввод/отрисовка подтверждены. Один последовательный замер не доказывает устойчивую регрессию или её отсутствие. Исправленный финальный бинарник будет измерен отдельно.
