# BENCH-задача: зависание супер-вкладок (открытие/удаление/правка)

Это соревновательная задача для параллельной оценки ИИ-агентов (Kimi vs Codex).
Оба агента получают ОДИНАКОВЫЙ текст, стартуют из ОДНОГО коммита, работают в
СВОИХ ветках. Победитель — по критериям внизу, не по скорости ответа.

## Симптомы (от пользователя)

Супер-вкладки подвисают:
- при открытии уже созданных супер-вкладок;
- при удалении супер-вкладки;
- при редактировании супер-вкладки.

Создание и переключение, судя по ощущениям, работают нормально.

## Журнал (фрагмент реального прогона)

```
при старте убито сирот-движков: 0
svmwdpvyl5: запуск ок, окно 53215790
pokazat_dvizhki(-): vidno=false / готово
otkryt(svmwds6rx2): вход
pokazat_dvizhki(-): vidno=true / готово
svmwds6rx2: запуск ок, окно 8259482
pereklyuchit(...): вход (подряд несколько)
zakryt(svmwds6rx2): останавливаю движок / движок остановлен
```

Функции `otkryt`, `zakryt`, `pereklyuchit`, `pokazat_dvizhki` — живут в
`desktop/src-tauri/src/` (Rust; файлы `brauzer.rs`, `cef_dvizhok.rs`, `okna.rs`),
фронт — `desktop/src/App.tsx`. Код и идентификары на транслите — это нормально,
так заведено в проекте.

Важно из истории коммитов: 0.2.3 и 0.2.4 УЖЕ выносили «все тяжёлые команды вне
UI-потока» и убирали кросс-процессные SetFocus. Значит зависание либо осталось
в каком-то из этих путей (открытие существующей/удаление/правка), либо это
новая регрессия. Не предполагай — воспроизведи и докажи.

## Правила

1. **Старт**: ветка от текущего `origin/master` (`aa0dcd5` или новее):
   `git checkout -b bench/<agent>-supertabs origin/master`, работать только в ней.
2. Проект публичный: никаких секретов, личных путей, упоминаний инфраструктуры
   в коде и коммитах.
3. **Сначала воспроизведи** зависание (сборка desktop-приложения, реальный запуск,
   реальные действия с супер-вкладками). Если воспроизвести не смог — это тоже
   результат, но нужны доказательства попыток.
4. Диагностика и правки — только после воспроизведения. Комментарии в коде не
   плодить, код на транслите/русском как в проекте.
5. Тяжёлые операции — вне UI-потока (паттерн проекта: команды + журнал).
6. Каждый коммит — компилируемое состояние.

## Критерии готовности (все обязательны)

- [ ] Открытие созданной ранее супер-вкладки — без заметного фриза (<1 с)
- [ ] Удаление супер-вкладки — без фриза
- [ ] Правка супер-вкладки — без фриза
- [ ] Создание и переключение супер-вкладок — по-прежнему работают
- [ ] Приложение собирается (`cargo build` в desktop/src-tauri, см. гайд проекта)
- [ ] Проверено реальным запуском, не «должно работать»

## Отчёт (в конце, файлом REPORT-<agent>.md в корне репо)

1. Воспроизвёлось ли зависание, как именно проверял.
2. Корневая причина (что реально тормозило).
3. Что изменено (коммиты, список).
4. Как верифицировал критерии (доказательства: логи, замеры, скринкаст-описание).
5. Сколько раз пришлось вмешиваться человеку-пользователю (метрика для сравнения
   агентов — чем меньше, тем лучше).
