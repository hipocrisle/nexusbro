# Диагностика NexusBro — стартовый контекст для сессии

Этот файл пишется для агента, который работает с репозиторием НА МАШИНЕ
с воспроизводимыми багами (Windows). Читай первым. Обновляй по ходу
находок — этот файл общий для всех сессий.

## Продукт

NexusBro — оболочка (Tauri 2 + React) поверх готового ungoogled-chromium.
«Супер-вкладка» = отдельный процесс движка со своим профилем и своим
прокси, окно движка встраивается в наше (Windows: `SetParent` +
стили; Linux: X11 reparent). Полоса вкладок — наша, движок живёт под ней.

## Где что лежит на машине пользователя

- Установка: `%LOCALAPPDATA%\Programs\NexusBro\`
  (`nexusbro.exe`, `chromium\nexusbro-engine.exe` + весь движок, `binaries\xray.exe`).
- Данные: `%LOCALAPPDATA%\NexusBro\`
  - `vkladki.json` — открытые супер-вкладки (настройки каждой);
  - `sohranennye.json` — сохранённые (закрытые) вкладки;
  - `aktivnaya.json` — какая вкладка была активна при выходе;
  - `profili\<id>\` — профиль конкретной вкладки:
    `engine.log` (журнал движка, stderr), `Default\Preferences`,
    `SingletonLock` и прочие блокировки профиля.

## Ключевой код

- `desktop/src-tauri/src/brauzer.rs` — поиск/запуск/остановка движка,
  удаление блокировок профиля, `pribit_proshlyh_dvizhkov` (убийство
  сирот по имени `nexusbro-engine.exe`), запись `restore_on_startup`.
- `desktop/src-tauri/src/okna.rs` — встраивание (Windows: модуль
  `sistema`, `vstroit`/`najti_okno`/`nash_li`/`spryatat_chuzhie`).
- `desktop/src-tauri/src/lib.rs` — команды, сторож окон (раз в 1 с
  ищет живое окно движка и пересозданное встраивает заново), журнал
  `zapisat_v_zhurnal`, кнопка 🛠 выводит `diagnostika()` — копируй её
  вывод в разбор.
- `desktop/src/App.tsx` — полоса вкладок, диалоги, меню.

## Аргументы запуска движка (сейчас)

```
nexusbro-engine.exe --user-data-dir=<профиль> --no-first-run
  --no-default-browser-check --disable-features=Translate,MediaRouter
  --force-dark-mode --enable-features=WebContentsForceDark
  --enable-logging=stderr [--proxy-server=http://127.0.0.1:порт] [адрес]
```

## Проверенные опытом факты (не теории!)

1. **Восстановление сессии работает ТОЛЬКО после чистого выхода движка.**
   После kill/TerminateProcess Chromium НЕ восстанавливает вкладки ни с
   каким флагом (проверено: `--restore-last-session` бесполезен; пузырь
   «восстановить» — единственный путь после краха, мы его не скрываем).
   Чистый выход = WM_CLOSE (Windows, таймаут 3 с, ТОЛЬКО
   `SMTO_ABORTIFHUNG` — флаг `SMTO_NOTIMEOUTIFNOTHUNG` ждёт бесконечно,
   на нём висли закрытия) или SIGTERM (Linux). После чистого выхода
   настройка `session.restore_on_startup=1` в `Default\Preferences`
   (пишем ДО запуска) восстанавливает вкладки сама. Проверено на живом
   движке end-to-end.
2. **«Движок умер сразу (exit code 0), журнал пуст»** = стартовавший
   Chromium видел профиль занятым (сирота или `SingletonLock` после
   жёсткого убийства), переслал команду живому экземпляру и вышел с
   кодом 0. Его окно-ошибка «профиль используется» — обычное видимое
   окно, наш поиск его находил и ВСТРАИВАЛ как рабочую вкладку
   (отсюда «кнопки управления на месте», «клик открывает новое окно»).
   Лечение в коде: удаление блокировок перед стартом + проверка жизни
   процесса ДО встраивания. Если воспроизводится — смотри, КТО держит
   профиль (диспетчер процессов / `Get-Process` в PowerShell).
3. **Chromium пересоздаёт своё окно** (не выяснено при каких условиях
   именно на машине user'а — возможно смена DPI при переносе между
   мониторами). Зомби-окно остаётся нашим потомком (`nash_li=true`),
   живое новое — верхнеуровневым, поверх нашего, ест клики. Сторож
   должен встраивать живое окно, если оно другое, чем отслежённое.
4. **Убийство процесса, к которому прикреплены через AttachThreadInput,
   вешает нашу очередь ввода.** Порядок строго: открепить и убить на
   нашем UI-потоке (так в коде).
5. Встраивание ребёнка в окно другого потока ломает клавиатуру без
   AttachThreadInput; фокус после Alt-Tab возвращаем движку при
   `Focused(true)`.
6. Плагинам Tauri 2 нужен `capabilities/default.json` — без него
   updater/dialog блокируются ACL (было: «plugin:updater|check not
   allowed by ACL»).

## Актуальные жалобы user'а (последний цикл, v0.1.8–0.1.9)

- Окно движка всё ещё с кнопками управления и «живёт своей жизнью»
  (главная подозреваемая — пересоздание, пункт 3 выше; надо увидеть
  глазами через Process Explorer / Spy++: сколько окон у
  nexusbro-engine.exe и какие у них стили).
- Сессии не восстанавливались (должно чиниться чистым выходом, п.1;
  проверить глазами: exit type в профиле, возвращается ли окно после
  перезапуска программы).
- Редиагностировать: 🛠 в программе → копия; плюс ручной запуск движка
  из PowerShell с теми же аргументами и наблюдение.

## Как воспроизвести руками (Windows, PowerShell)

```
# убить всех сирот:
Get-Process nexusbro-engine -ErrorAction SilentlyContinue | Stop-Process -Force
# запустить движок как делает программа:
& "$env:LOCALAPPDATA\Programs\NexusBro\chromium\nexusbro-engine.exe" `
  --user-data-dir="$env:LOCALAPPDATA\NexusBro\profili\TEST1" `
  --no-first-run --no-default-browser-check --enable-logging=stderr
# смотреть: сколько окон, с какими стилями, что в engine.log,
# какие файлы появляются в профиле (SingletonLock и т.д.)
```

## Правила для сессии

- Это публичный репозиторий: никаких личных данных, путей кроме
  стандартных, секретов.
- Коммить и пушь смысловыми кусками; если другая сессия (Linux, CI)
  активна — договорись о ветке, не правьте main вдвоём.
- После правок: `cargo check` (при наличии тулчейна), лучше всего —
  открыть PR и прогнать CI. Релизы — тегом `v*` (версии в
  `package.json`, `tauri.conf.json`, `Cargo.toml` должны совпадать).
