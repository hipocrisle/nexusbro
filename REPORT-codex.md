# Проверка зависаний супер-вкладок — Codex

## Результат воспроизведения

Зависание **не воспроизведено**. Реальный GUI-прогон заблокирован ограничениями среды выполнения. Это не означает, что дефект отсутствует.

Ветка: `bench/codex-supertabs`. Исходный коммит: `aa0dcd5618373e31644d4a261780c81f74e442f6`. Перед карточкой прочитан гайд проекта. Рабочее дерево перед началом было чистым; карточка затем добавлена пользователем.

Попытки:

1. Подготовлен изолированный каталог пользовательских данных для проверки, чтобы не затронуть обычные профили.
2. Выполнен `Xvfb :91 -screen 0 1280x900x24 -nolisten tcp`. Завершился с кодом 1: `Cannot establish any listening sockets`. Полный вывод: [bench-artifacts/xvfb.txt](bench-artifacts/xvfb.txt).
3. Отдельная проверка создания Unix- и TCP-сокетов дала `Operation not permitted` для обоих типов: [bench-artifacts/socket-probe.json](bench-artifacts/socket-probe.json). Таким образом, заблокирован не только X11, но и локальный прокси, необходимый движку.
4. Предпринят запуск доступного исходного бинарника из локального кэша сборки с `NEXUSBRO_PROBA=2`, `DISPLAY=:91`, CEF и изолированными данными. Он завершился до действий с вкладками: `Failed to initialize GTK`. Вывод: [bench-artifacts/baseline-launch.txt](bench-artifacts/baseline-launch.txt). Этот бинарник не выдаётся за результат повторной сборки текущей копии.

Создание, открытие существующей вкладки, переключение, удаление и редактирование через GUI выполнить не удалось. Замеры времени этих операций отсутствуют.

5. После успешной повторной сборки запущен **бинарник из этой рабочей копии** с теми же параметрами: выход 101, снова `Failed to initialize GTK`. Вывод: [bench-artifacts/rebuilt-launch.txt](bench-artifacts/rebuilt-launch.txt).

## Корневая причина

Причина пользовательского зависания **не установлена**. Установленная причина невозможности проверки — запрет локальных сокетов в песочнице. Ошибку GTK нельзя считать воспроизведением зависания супер-вкладок.

## Изменения

Код приложения не изменён: правило 4 карточки разрешает диагностику и правки только после воспроизведения. Добавлены отчёт и свидетельства неудачной попытки запуска. Исправление на основании предположений не выполнялось.

Коммит результата: `bench: отчёт о проверке супер-вкладок и ограничениях GUI-прогона` (только отчёт и свидетельства; исправлений приложения нет).

## Проверка критериев

| Критерий | Результат |
|---|---|
| Открытие созданной вкладки без фриза, <1 с | Не проверено: GUI недоступен |
| Удаление без фриза | Не проверено: GUI недоступен |
| Правка без фриза | Не проверено: GUI недоступен |
| Создание и переключение работают | Не проверено: GUI недоступен |
| `cargo build` | Успешно, код выхода 0; 20 предупреждений |
| Реальный запуск и действия | Запуск предпринят; до GUI не дошёл |

Протокол frontend-сборки: [bench-artifacts/frontend-build.txt](bench-artifacts/frontend-build.txt).

Frontend: `npm ci --offline --ignore-scripts`, затем `npm run build` — успешно, TypeScript и Vite собрали 38 модулей. Обычный `npm ci --offline` сначала завершился ошибкой `EPERM` на проверочном вызове esbuild; установка без lifecycle-скриптов и непосредственная сборка прошли.

Rust: `CEF_PATH=<cef> CARGO_BUILD_JOBS=2 cargo build --offline` в `desktop/src-tauri` — успешно. Для ресурсов Tauri временно подключён установленный CEF как `desktop/src-tauri/cef`; после проверки ссылка удалена. Первый вызов без каталога ресурсов завершился ошибкой `resource path cef doesn't exist`; повторный завершился за 50,73 с. Протокол успешной сборки: [bench-artifacts/cargo-build.txt](bench-artifacts/cargo-build.txt). Автоматическое обновление версии самого пакета в Cargo.lock (0.2.3 → 0.2.4) отменено, чтобы оставить исходный код без изменений.

## Вмешательства пользователя

До старта выполнения карточки потребовалось одно вмешательство: пользователь поместил отсутствовавшую карточку в рабочую копию. После этого направлен один запрос на разрешение локальных сокетов в среде выполнения. На момент составления отчёта ответ ещё не получен. Дополнительные ручные действия с приложением не запрашивались.

## Что осталось

После предоставления среды с X11 и локальными сокетами требуется собрать и запустить исходную версию, воспроизвести именно пользовательские действия (включая открытие сохранённой вкладки и правку работающей), затем установить причину, внести исправление и повторить замеры. Проверки Windows также не проводились.
